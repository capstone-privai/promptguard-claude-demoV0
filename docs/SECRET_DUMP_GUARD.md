# 비밀 파일 덤프 가드

정우 분석("변형된 첫 출력은 remask와 placeholder를 둘 다 못 쓰게 만든다", 2026-11-21)에서 나온 문제를 다룬다.

## 문제

- **gold g16·g20, promptguard g16:** 모델이 비밀 파일의 정확한 바이트를 보려고 `od -c secrets/db_password.txt`를 실행했다.
- **탐지와 금고를 모두 피했다:** 출력은 글자마다 공백이 들어가고 줄 앞에 오프셋이 붙은 모양이라 탐지기가 값을 찾지 못했다. 금고에도 들어가지 않아 placeholder가 생기지 않았다.
- **서버로 갔다:** 모델은 그 출력에서 값을 읽어 Edit의 `new_string`에 원문으로 썼다. 그 호출이 다음 요청부터 대화 기록으로 서버에 갔다.
- **promptguard t14:** `od -c`로 토큰이 한 글자씩 띄어진 채 서버로 갔다.

출력 형식은 끝없이 만들 수 있으므로, 형식마다 파서를 만들어서는 다 막을 수 없다. 그래서 출력의 모양이 아니라 "출력이 비밀 파일에서 나왔는가"로 판단한다.

## `PG_SECRET_DUMP_GUARD=on|off` (기본 on)

Bash 명령 문자열을 보고, 한 파이프라인(`|`로 이어진 명령들)이 아래 두 조건을 모두 만족하면 그 명령의 출력 전체를 안내 문구 하나로 바꾼다.

1. **비밀 파일로 보이는 경로를 읽는다**
   - `.env`, `.env.*`, `secrets/` 아래 파일
   - 파일 이름에 `secret`, `password`, `passwd`, `credential`, `token`이 든 것
   - `*.pem`, `*.key`, `id_rsa*`, `id_ed25519*`, `.netrc`, `.npmrc`, `.pypirc`
2. **변형·덤프 도구를 쓴다**
   - `od`, `xxd`, `hexdump`(`hd`), `base64`, `base32`, `basenc`, `fold`, `rev`
   - `cut -c`(`--characters`)
   - `sed`: 한 글자 단위 치환(`s/./…/`, `s/\(.\)/…/`, `s/(.)/…/`)
   - `awk`·`python`·`node`·`perl`(`ruby`): 코드가 글자·바이트 단위로 쪼개거나 인코딩하는 경우. 예: `list(`, `ord(`, `.hex(`, `b64encode`, `.join(`, `split('')`, `charCodeAt`, `split //`, `unpack`

**바꾼 결과:**
- stdout은 `[PROMPTGUARD: 비밀 파일을 변형해 출력한 결과라 가렸습니다. 값은 placeholder로 다루고, 속성은 값을 출력하지 않는 명령으로 확인하세요]`가 되고, 나머지 문자열 필드(stderr 등)는 빈 값이 된다.
- 명령이 실패했으면 그 오류 문구 대신 같은 안내 문구로 거부한다.
- 명령 자체는 실행된다(파일 쓰기 같은 부수 효과는 그대로). 모델이 받는 결과만 바뀐다.

**가드 대상이 아닌 것:**
- 같은 경로를 `cat`이나 Read처럼 그대로 읽는 경우. 지금처럼 탐지기와 placeholder 경로를 탄다.
- 비밀처럼 보이지 않는 파일(`README.md`, `package.json`)을 덤프 도구로 보는 경우.
- `cat .env && od -c README.md`처럼 비밀 경로와 덤프 도구가 다른 파이프라인에 있는 경우.

**코드 속 경로:** `python -c "...open('secrets/x')..."`처럼 코드 안에 있는 경로는 `/`나 확장자가 있는 조각만 경로로 본다. 그래서 `tokens = [1, 2]` 같은 변수 이름은 경로가 아니다.

**감사 로그:** 가드가 동작할 때마다 `secret_dump_guarded` 행을 하나 남긴다. 담는 것은 걸린 도구 이름(`dump_tool`)과 세션 안 누적 횟수(`secret_dump_count`)뿐이다. 경로와 값은 남기지 않는다.

## `PG_SECRET_FILE_PRELOAD=on|off` (기본 off)

비밀 파일로 보이는 경로를 이름에 담은 Bash 명령이 있으면, 실행 전에 Mod가 그 파일을 직접 읽어 금고에 미리 넣는다. 덤프 명령뿐 아니라 `cat`도 해당한다. 그러면 그 값이 나중에 어디에 원문으로 나와도(Edit 입력이 기록으로 다시 나올 때 포함) 재마스킹이 가린다.

- **넣는 조건:**
  - 파일이 256바이트 이하
  - 앞뒤 공백을 뺀 내용이 한 줄이고 8자 이상
  - 이미 자리표시자 모양이 아닌 것
- **넣지 않는 것:** 큰 파일, 여러 줄 파일(.env 같은 것), 짧은 값, 없는 파일, 읽을 수 없는 파일. `~`로 시작하는 경로는 펼치지 않으므로 건너뛴다.
- **유형:** 파일 이름에 password·passwd·pwd가 있으면 `PASSWORD`, token이 있으면 `TOKEN`, 그 밖은 `SECRET`이다.
- **같은 값은 같은 자리표시자:** 나중에 탐지기가 같은 값을 찾으면 같은 자리표시자를 쓴다. 이를 위해 `placeholder()`가 원문으로 이미 등록된 자리표시자를 먼저 찾게 했다. 탐지기의 `value_hash`는 worker마다 다른 키로 만든 HMAC이라, Mod가 미리 같은 키를 만들 수 없기 때문이다.

**기본값을 끈 이유:**
- **잘못 가릴 위험:** 비밀이 아닌 작은 파일도 이름만으로 금고에 들어간다(예: `token_count.txt`에 든 숫자). 그러면 그 내용이 다른 곳에 나올 때마다 가려진다. 8자 미만은 넣지 않지만, 8자 이상 값도 흔한 문자열일 수 있다.
- **아직 덮지 못하는 경우:** 파일이 모델에게 한 번도 보이지 않았는데 자리표시자 번호가 생긴다. 상대 경로는 세션 작업 폴더 기준이라, 명령 안에서 `cd`한 뒤의 경로는 엉뚱한 파일을 읽거나 못 읽는다.
- **덤프 가드만으로 원래 사고는 막힌다.** 미리 넣기는 탐지기가 `cat`에서도 못 찾는 맨 비밀번호 파일을 위한 보강이다. 지표 2에서 효과와 오탐을 잰 뒤 켤지 정한다.

## 안내문 보강 (`PG_PLACEHOLDER_GUIDE`)

안내문 끝에 다음 문장(영어)을 더했다.

> 비밀 파일이나 가려진 값을 od, xxd, hexdump, base64, 글자 쪼개기, 일부만 자르기 같은 방식으로 출력하지 마라. 특수문자 포함 여부나 길이 같은 속성이 필요하면 값을 출력하지 않는 명령으로 확인하라(예: `grep -c '[$]' 파일`, python으로 조건 결과만 출력).

- 늘어난 길이는 371자, 약 90토큰이다(글자 수로 어림).
- 안내문 전체는 `PG_RESTORE_ESCAPED=on`(기본)일 때 763자에서 1,134자로, off일 때 627자에서 998자로 늘었다.
- 시스템 프롬프트라 같은 세션의 두 번째 요청부터는 대부분 캐시 읽기로 계산된다.

## 한계

- **경로를 조립하는 경우:** 변수(`f=secrets/x; od -c $f`), 명령 치환으로 다른 곳에서 경로를 가져오는 경우(`od -c "$(cat paths.txt)"`. `$(ls secrets/*)`처럼 명령 안에 비밀 경로가 보이면 걸린다), 글롭(`od -c sec*/*`), 심볼릭 링크(`ln -s secrets/x a; od -c a`), 다른 이름으로 복사한 뒤 덤프하는 경우는 명령 문자열에 비밀 경로가 보이지 않아 걸리지 않는다.
- **Bash 밖의 도구:** PowerShell, 다른 MCP 도구, 하위 에이전트가 직접 실행하는 명령은 보지 않는다. Read는 파일을 그대로 읽으므로 탐지기 경로를 탄다.
- **도구 목록 밖의 변형:** `head -c`, `tail -c`, `strings`, `printf '%q'`, `cat -A`, 목록에 없는 언어와 코드 형태는 걸리지 않는다. 출력 형식을 다 적을 수는 없으므로 목록은 사고가 난 형식과 흔한 덤프 도구로 정했다.
- **비밀처럼 보이는 이름의 일반 파일:** `tokenizer.py`, `password_policy.md`처럼 이름만 비밀처럼 보이는 파일을 덤프 도구로 보면 걸린다(오탐). 지표 2에서 이 횟수를 센다.
- **작업 폴더 밖의 `cd`:** 가드 판단은 경로의 모양만 보므로 `cd`와 상관없이 동작한다. 미리 넣기는 세션 작업 폴더 기준으로 읽는다.

## 다음 과제

- **실제로 연 파일을 보기:** `strace -e openat`(Linux)이나 그에 해당하는 방법으로 명령이 실제로 연 파일을 보고 판단하는 방식. 경로를 조립하는 경우까지 덮지만, 실행 환경마다 방법이 다르고 비용이 든다.
